You are an independent systems reviewer for an experimental AI player in Daggerfall Online (DFO). Challenge our architecture and propose better or simpler methods. ## Goal and priorities

The agent should eventually play as a normal player: explore, fight, use magic, manage equipment, trade, talk to NPCs and players, travel, pursue quests, recover from failure, and maintain its own persona and memory. Accurate, dependable game control with the fewest useful model calls and tokens is the priority. The user's NEW desired architecture has three tiers: Luna handles short-term actions and tactics; Terra 6.1 handles medium-term and session planning; Sol 6.1 handles high-end decisions, post-session review, improvement planning and implementation. The exact Luna variant has not been selected. Our implemented baseline still has Terra as tactical pilot and Sol as planner; do not confuse the proposal with deployed behavior. Models must retain authority over objectives and courses of action; local deterministic code may execute, navigate, react, and verify within their chosen intentions. A loop that runs cheaply but makes no useful progress is a failure.

Improvements should be testable and applied while the game remains open, with preserved character memory and plans, bounded execution, clear rollback, and comprehensive logs. Reuse existing DFO agent foundations wherever they are suitable. Earlier project restrictions are not a blanket constraint on this separate project. Preserve unrelated files and evidence. Subscription-only model operation is required: pause on exhaustion, with no automatic API billing fallback. Use ordinary player input/action hooks; exact player pose/vitals are a declared precision assist. Do not solve navigation or combat by revealing hidden maps/enemies, teleporting, spawning, or changing health/damage.

## Evidence so far

The earlier screenshot/browser-input practice trial was stopped after 21m18s at the user's request because allowance consumption was high. It issued 176 Terra requests and 9 Sol requests; logged responses reported 2,215,985 input tokens, of which 736,000 were cached, plus 18,131 output tokens. Cached tokens are already part of input, not additional input. It recorded 167 dispatch receipts, six action errors and one fatal controller-busy error. No escape or kill was verified. Common movement decisions were only 1–2.5-second holds despite longer holds being available. Pointer lock failed in headless Edge; keyboard turning worked. These are observations, not proof of a single root cause.

A new native control port now passes 121 model-free tests, including an overlapping 83-test controller benchmark. Static engine bundling and imports passed. Live native movement, combat, hot repair, online operation, and a completed one-hour trial remain unverified. There is no measured native-play token saving yet. Passing fake/recorded checks does not establish gameplay competence.

## Current implemented two-tier baseline

1. A separate project with its own Git repository lives at `%USERPROFILE%\Documents\DFO\DFO-TerraSol`. Its ignored engine checkout is pinned at `e4f09316684d78d194553d3c94cbaa9bbdaa9b7b`. Original DFO agent workspaces are reference sources. Vendored bridge/Body sources, hashes and modifications are tracked.
2. A headless Edge page is connected through Playwright/CDP. The local driver exposes observation, native intent/status, trusted UI action, stop, pause, resume and shutdown endpoints. The native bridge plugs into the normal world host's player bindings and look/attack hooks. Native control is default; browser diagnostic control is explicit. There is no silent timed-input fallback.
3. The bridge exposes player-local pose/vitals, weapon/UI state, current visible foes/things, sensed scans and sequenced events. Frame/page/generation checks reject stale actions. Visible foes receive opaque frame-scoped IDs, stable across movement; acceptance refreshes the current observation by ID. Missing targets are rejected rather than reassigning old list indexes.
4. The reused Body runs every 50ms. It handles steering, obstacle/footing guards, weapon draw, low-enemy aim, attack cadence, short threat retention and observed interaction outcomes. Reused place memory, routing and frontier exploration operate over observed geometry.
5. Terra chooses one bounded intent: turn, look, goto, use, explore, fight, retreat or stop. The executor defaults to 30 seconds, caps at 90 seconds, and renews a two-second Body lease. The worker polls locally every 250ms with no model call while the task is running. Completion/interruption returns control to the model. Outcomes distinguish completed, interrupted, blocked, failed, cancelled and expired; attack dispatch is never counted as a kill.
6. Fight/retreat temporarily select the Body's nearest-hostile policy. The chosen target must remain the currently sensed nearest hostile; a per-tick guard releases and disables control if it changes, observation goes stale, or health reaches a model-chosen percentage floor (default 35%). Noncombat tasks yield on damage. Target loss is an interruption, not proof of a kill. Examine whether these rules cause excessive interruption or suppress competent combat.
7. Trusted browser UI input first cancels/releases Body authority. A serialized control queue and stop latch prevent concurrent controllers. Body/frame/driver changes cancel execution; Body replacement retires the previous timer and installs disabled. Bridge installation uses managed hashes and refuses unrelated edits. Runtime hot repair exists but the new native path still needs live verification.
8. Each model decision currently receives a fresh screenshot plus UI text/controls, persona, retrieved memory, plan, recent decisions and native state/targets. The current native context can duplicate foes in state and target entries. Sol's planning context uses screenshot/UI context and prior outcomes, rather than the same full native observation. Local polls log progress and checkpoint memory. Review unnecessary image/context/logging and checkpoint costs; distinguish actual behavior from the plan's aspirations.
9. Sol is called for initial strategy, explicit escalation and repeated failures. Identity and memory persist across worker epochs. Model transport uses authenticated Codex subprocesses, strict JSON responses and subscription authentication. Developer-agent usage is not included in playing-role telemetry and is reported unavailable, not zero.
10. Reports retain terminal evidence and counts by intent kind, separating stop/look receipts from progress. Complex equipment, commerce, magic, quest and social workflows are not established merely because generic UI clicks exist.
