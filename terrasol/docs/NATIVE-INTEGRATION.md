# Native control integration

Native is the default for both `node src/browser.mjs --headless` and `node src/main.mjs`; explicitly choose `--control browser` on both commands for the prior screenshot/timed-input diagnostic. Do not launch either as part of model-free verification. The native driver installs the tracked bridge before the game starts and adds `?agent=1` to a newly opened game page. An already attached game page is preserved, never reloaded: if it was opened without the bridge, native reports unavailable until the operator arranges a fresh compatible session.

Before the world bridge exists, creation, loading, and front-door screens remain accessible with trusted browser UI actions; native movement remains unavailable. Unchanged loading is waited out locally. Once in the world, select a current target by its index in `targets`; the worker sends the exact observed object and the driver rechecks generation and frame, then refreshes a moving foe by its frame-scoped observed target ID before starting. A vanished foe is rejected; the old index is never reassigned. A ground target is verified against observed navigation memory by the executor. Native observation does not require pointer lock. For fight or retreat the model may set a 0�100 percent health floor; the default is 35 percent. Other routines yield on damage. Native routines execute locally with finite Body leases and polling; model requests occur after terminal outcomes or other decision points. Browser UI actions first disable and release the Body. Stop, pause, navigation and shutdown invalidate and cancel execution. Browser mode retains its original action schema and prompts.

Report metric v2 separates turn, stop, look, weak UI changes and raw completion receipts from evidenced state transitions, provides outcome counts by intent kind, and includes terminal native evidence and computes calls and playing-role input tokens per evidenced movement, separation or place transition only when available. These transitions do not prove useful gameplay. Cached input is a subset of input. Developer/engineering usage is unavailable, not zero. A dispatch is never a verified outcome. Unit and fake-adapter checks do not establish live gameplay reliability; game, pointer-lock behavior, and paid model trial remain untested in this port.
